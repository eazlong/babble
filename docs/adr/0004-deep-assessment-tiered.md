# 深度补评分层：voice-service 重跑 ASR 先行，临界升级 LLM

深度补评采用两段式分层管道：先用 voice-service 重跑 ASR 修正交互尝试文本，仅当"修正后仍无法判定掌握度"的临界 case 才升级到 LLM 评判（ASR 文本 + 场景内容 + 目标句 → 掌握分 + 理由）。

## 理由

补评的核心痛点是实时快评听错/判错。重跑 ASR 能修掉最常见、最便宜的"听写错误"类，voice-service 已有能力，不新增依赖。但"听写对了"不等于"掌握了"——例如孩子把 "Her name is A-Ling" 说成 "Her name A-Ling"，ASR 文本正确捕获却缺谓语，规则打分判不出语法掌握度，必须靠 LLM 结合目标句与场景内容判。

分层把 LLM 高成本约束在 C∩D 筛出的窄子集中：能进补评池的本来就是少数关键资料交互尝试，其中再只有一小部分 ASR 修正后仍模糊需升级 LLM，整体成本可控。

## 后果

两段式管道比单一能力复杂，须定义清晰的"何时升级"判定规则，否则 LLM 滥用或该升级没升级。升级判定规则需可配置、可观测。
