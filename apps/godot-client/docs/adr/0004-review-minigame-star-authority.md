# 复习小游戏的星辉口径：以 Star Economy 的 stars_per_response 为唯一权威

- Status: accepted
- Date: 2026-09-22
- Scope: apps/godot-client

## Background

> /grill-with-docs 把归卷厅补成真正可玩的小游戏：表现层游戏化 + 数据/奖励闭环。
>
> A：星辉到底怎么发？现在两份文档打架，代码还反着做。

三处冲突（全部经代码与文档核验）：

1. **星级范围不同。** `design/gdd/star-economy.md` §3.1（状态 ✅ Approved）定义
   `stars_per_response = f(LXP_score)`，固定 5 档：0–39→1★、40–59→2★、60–74→3★、
   75–89→4★、90–100→5★。而 `design/gdd/word-spirit-library-scene.md` §7.3（📝 Draft）
   自定 3 档：清晰(≥0.85)→3★、接近(0.65–0.84)→2★、回放自评接受→1★。
2. **输入量不同。** 场景文档按 **ASR 共鸣度/置信度** 发星，Star Economy 按 **LXP 分数** 发星。
3. **下界不同。** 场景文档允许 **0 星**（再试/需要帮助/机会耗尽），Star Economy 最小 1★。

而场景文档 §7.3 自己写着"星星发放通过 Star Economy 系统的 `stars_per_response` 接口，
**本场景不自行定义星星计算公式**"——紧接着下一行就自定了一套 3 星表，自相矛盾。

代码现状与两份文档都不一致：`WordSpiritLibraryArchiveHallController._grant_stars()` 执行
`manager.lxp_score += star_count * star_to_lxp_multiplier`（配置里 `star_to_lxp_multiplier: 10`），
即 **星辉 → LXP**；而两份文档的方向都是 **LXP → 星辉**。全客户端没有任何一处实现
`stars_per_response`，它只存在于 GDD 里。

## Decision

1. **权威 = Star Economy GDD §3.1。** 归卷厅不再自定义星级范围；场景文档 §7.3 的 3/2/1 星表作废。
2. **"一次回应"的定义 = 一次词牌刻印结算。** 拼写正确并进入朗读判定后产生的那一次结果，
   才是 Star Economy 意义上的一个 response；拼写阶段、指令、no-speech 都不是。
3. **映射链 = 共鸣度 → LXP → 星辉**，具体取值：

   | 本次结果 | LXP | 星辉 | 铭文表现 |
   |---|---|---|---|
   | 清晰（ASR 置信度 ≥ 0.85） | 95 | **5★** | 金色发光 |
   | 接近（0.65–0.84） | 80 | **4★** | 银色发光 |
   | 示范模式后刻印 | 65 | **3★（封顶）** | 银色微光 |
   | 录音回放自评接受（ASR 不可用降级） | 50 | **2★** | 微光 |
   | 再试 / 需要帮助 / 朗读机会耗尽转墨影 | — | **不发星** | 不刻印 |

4. **归卷厅不发星不等于罚分。** 未通过不产生星辉，但墨影词牌照进重试队列
   （GDD §3.3"词牌保留为墨影词牌进入重试队列"），`InteractionAttempt` 与 timeline event 照记。
   Star Economy 的 1–5★ 描述的是"玩家做过一次回应"，没回应自然没有星辉，不构成对儿童的扣分。
5. **旋钮同步：** `demonstration_star_cap` 由 `1` 改为 `3`（5 星制下的"示范后封顶"）；
   删除 `star_to_lxp_multiplier`（它在做方向相反的事）；新增 `star_to_lxp` 映射表，
   把第 3 条的 LXP 取值放进 `assets/data/word_spirit_library_scene.json`，不硬编码。
6. **反馈语/音效/特效取 Star Economy §3.1 表格对应档位的列**，场景不另写一套鼓励语。
7. **本轮不改主线对话场景。** 长安集市等仍按 `lxp_reward` 一次性结算；将来它们接入
   `stars_per_response` 时，以本 ADR 的口径为准。

## Rationale

- Approved 文档优先于 Draft 文档：Star Economy 已审查通过，场景文档还是初稿，
  且场景文档自己声明"不自行定义公式"，所以让场景服从 Star Economy 是文档体系内的最小改动。
- 5 星制比 3 星制更适合这个场景：Star Economy 的最小 1★ 意味着"哪怕说得不好也被听见了"，
  比场景文档的 0 星更符合 GDD §3.3"不使用严厉分数"和场景文档 §11.5"识别失败不是错误，
  是没听清"的儿童向原则。
- 保留"共鸣度"作为**玩家可见的反馈语言**（清晰/接近/再试/需要帮助），星辉作为**结算货币**，
  两者不再混为一谈——这正是两份文档打架的根源。
- 把 LXP 取值放进配置文件而不是写死在代码里，是因为这些数字会被 `letter_recognition_record`
  与真实儿童数据校准（场景文档 §13.3），必须能调。
- 删掉 `star_to_lxp_multiplier` 而不是保留兼容：它产生的是反方向的数值，
  留着只会让下一个读代码的人再次踩进同一个歧义。

## Edge Cases and State

- **ASR 不可用时**（场景文档 §6.5 降级路径）：回放自评"accept/ok/yes"→ LXP 50 → 2★；
  说 "retry/again" 不结算、不发星，仍算一次朗读机会。
- **示范模式**（§7.4）：示范后朗读通过 → 3★ 封顶，不再使用"星星减半"的表述
  （"减半"在 5 星制下无定义）。
- **连续失败**：第 2 次朗读未通过触发示范模式；示范后仍未通过 → 转墨影，0★，
  但 `error_record` 与墨影队列照写。
- **no-speech**：不消耗朗读机会、不结算、不发星（CLAUDE.md §4 的记录链路不变）。
- **同一词牌重复刻印**：不存在——刻印成功即从词池移出，失败进墨影队列下次优先回流。
- **阵法充能**（ADR 0003 第 4 条 + 术语表"复习单元"）：充能数的是一张词牌**走到终点**——
  刻印成功（2★–5★）与转墨影（不发星）**都 +1**，与拿了几星无关；中间态的重试
  （"再试"/"需要帮助"且朗读机会未尽）不是终点，**不**计入充能。
  星辉与充能是两套账：星辉看"有没有有效回应"，充能看"有没有结算完一个复习单元"。
